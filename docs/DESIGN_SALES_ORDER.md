## 1. 背景与目标

面料报价客户接受之后，业务需要一个真正往下走的单据：明确**买什么面料、什么颜色、多少数量、多少钱、什么时候要货、货发到哪、发出了没有**。

目标：把「客户已接受的报价」落成一张可执行、可追踪的销售订单，并让订单金额与毛利口径和报价单完全一致，便于对照。

## 2. 范围

**本次做**

- 销售订单列表：搜索、状态/客户/面料筛选、交期范围筛选、逾期未交付提示。
- 手工新建订单：选客户（+ 联系人）、选面料（同一面料可多行）、填数量与单价、自动算含税金额。
- 从报价单转订单：把「客户已接受」的报价单明细落成订单草稿。
- 明细行可关联采购货源与采购报价，带出 CNY 参考成本，**允许手工覆盖或清空**。
- 订单详情：条款 + 收货信息 + 明细表（金额、成本、毛利）+ 交付进度。
- 状态推进：确认 / 开始备货 / 发货 / 完成 / 取消。
- 交付登记：按明细行登记已交付数量，列表与详情显示交付状态。

**本次不做**

- 采购订单、向供应商下单的独立单据。
- 发货单、物流单号、运费、签收。
- 收款、应收、发票、对账。
- 库存扣减与出库（留到路线图第 7 条库存模块；本期已交付数量是**手工登记**，不产生任何库存变动）。
- 打印导出（订单 PDF/Excel）。
- 审批流、权限分级、多币种以外的币种、汇率自动抓取。
- 与寄样、报价的自动联动（转订单是一次性复制，不是实时同步）。

## 3. 关键概念界定

| 概念 | 含义 | 数据来源 |
| --- | --- | --- |
| 客户报价 | 我给客户的售价方案 | `CustomerQuote`（已存在，**本期不改**） |
| 销售订单 | 客户真正下给我的采购指令 | 本期新增 |
| 转订单 | 把已接受报价的价格与条款**复制**成订单草稿 | 一次性行为，此后两侧互不影响 |
| 采购货源 | 这批货我从哪家供应商/车间拿 | `FabricSupplier`（已存在，只读引用） |
| 参考成本 | 下单当时的采购价副本，**恒为 CNY**，可手工覆盖 | 存于订单明细行 |
| 已交付数量 | 实际发给客户的数量，**手工登记**，累计不超过订单数量 | 存于订单明细行，不联动库存 |

**硬性约束**

1. 订单**只读取**报价、面料、采购货源、采购报价，永不回写。报价变了、供应商涨价了，已确认的订单不受影响。
2. `tenantId` 全程隔离；跨租户资源一律当作不存在（404）。
3. 金额走 `Decimal`，只读 API 输出十进制字符串；派生值由前后端共用的同一份计算函数产出。

### 4.3 派生字段（不落库，前后端共用同一份计算规则）

设 `rate = exchangeRate`，`tax = 行税率 ?? 表头税率 ?? 0`：

- 不含税金额 = `quantity × unitPrice`（订单币种）
- 含税金额 = 不含税金额 × (1 + tax)（订单币种）
- 单价折算 CNY = `unitPrice × rate`
- 成本合计（CNY） = `costPrice × quantity`；无 `costPrice` 时该行显示「无成本参考」
- 毛利（CNY） = `quantity × (unitPrice × rate − costPrice)`
- 毛利率 = 毛利 ÷ (`quantity × unitPrice × rate`)
- 未交付数量 = `quantity − deliveredQuantity`
- 订单合计：不含税金额合计、含税金额合计、成本合计、毛利合计、毛利率（所有行的同种币值与 CNY 分别求和）

**交付状态（派生，不改库）**

| 状态 | 判定 |
| --- | --- |
| 未交付 | 所有行 `deliveredQuantity = 0` |
| 部分交付 | 既有 > 0 的行，也存在未完成的行 |
| 已交付 | 所有行 `deliveredQuantity ≥ quantity` |

**逾期提示（派生，不改库）**：`requestedDeliveryDate < 今天` 且交付状态 ≠ 已交付，且订单未完成/未取消时，列表与详情显示红字「逾期 N 天」。与报价单超期一致，只作提示。

> 与报价单完全一致的口径：金额用订单币种展示，成本与毛利一律折算 CNY，USD 单在毛利旁标注「按汇率 X 折算」。建议复用并扩展 `src/lib/customer-quote-math.ts` 的既有规则，避免两套算法。

## 5. 状态机

```
draft ──确认──> confirmed ──开始备货──> producing ──发货──> shipped ──完成──> completed
  │                │                       │
  └────────────────┴───────────────────────┴──取消──> cancelled（终态，须填原因）
```

| 状态 | key | 中文 | 可编辑 | 可否取消 |
| --- | --- | --- | --- | --- |
| 草稿 | `draft` | 草稿 | 是 | 是 |
| 已确认 | `confirmed` | 已确认 | 是 | 是 |
| 备货 / 生产中 | `producing` | 备货中 | 否 | 是 |
| 已发货 | `shipped` | 已发货 | 否 | 否 |
| 已完成 | `completed` | 已完成 | 否 | 否 |
| 已取消 | `cancelled` | 已取消 | 否 | —（终态） |

**规则**

1. 只能按箭头向下流转，不支持回退；`cancelled` 与 `completed` 是终态。
2. 「发货」要求：订单至少有一行 `quantity > 0`（必然满足），不校验库存（本期无库存）。
3. 「完成」要求：交付状态 = 已交付，**或**用户确认后允许直接完成（推荐在详情里给出「仍有未交付数量」的二次确认）。
4. 「取消」必须填 `cancelReason`，写入操作日志。
5. 状态变更走单独接口，与其它字段隔离（同报价单的做法）。

新增配置组 `sales_order_status`（草稿/已确认/备货中/已发货/已完成/已取消），稳定英文 key 入库，中文显示由 `ConfigOption` 负责。

## 6. 报价单转订单

**入口**：客户报价单详情里「转为订单」按钮，仅 `accepted` 状态的报价单可见。

**规则**

1. 来源报价单必须是本租户的 `accepted` 报价；其余状态返回 400 并提示。
2. 复制关系：客户、联系人、订单币种、汇率、贸易条款、交货方式、付款条款、税率全部从报价单表头带入；每行复制面料、参考成本、税率、色号备注、数量（**报价里数量为空的行，订单数量留空并要求用户补填**）。
3. `sourceQuoteId` / `sourceQuoteItemId` 记录来源，之后两侧互不影响：改报价不改写订单，改订单也不影响报价。
4. 转出后生成一张 **草稿** 订单，之后仍可修改；报价单本身状态保持 `accepted` 不变。
5. 同一张报价单**允许重复转**（比如分批下单），不做唯一约束，仅在 UI 上提示「该报价已生成 N 张订单」。为追溯方便，订单详情展示来源报价单号。
6. 报价单超期不影响转单，只在创建时把超期信息写进备注提示。

## 7. 接口设计（草案，待确认后实现）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/sales-orders` | 分页列表，支持 `q`、`status`、`customerId`、`fabricId`、`deliveryStatus`、`from`、`to`、`page`、`pageSize` |
| POST | `/api/sales-orders` | 手工新建，含明细；事务写入 + 操作日志 |
| POST | `/api/sales-orders/from-quote` | body `{ quoteId }`，按 §6 生成草稿 |
| GET | `/api/sales-orders/[id]` | 详情，含派生金额与交付状态 |
| PATCH | `/api/sales-orders/[id]` | 仅 `draft` / `confirmed` 可改，全量替换明细行 |
| PATCH | `/api/sales-orders/[id]/status` | 状态流转，`cancelReason` 在取消时必填 |
| PATCH | `/api/sales-orders/[id]/delivery` | body `{ items: [{ id, deliveredQuantity }] }`，仅维护交付数量，不改单价；`producing` / `shipped` 可用 |

**统一约定**

- 模块名（操作日志）：`sales_order`。
- 所有读写带 `tenantId`；跨租户资源返回 404。
- 金额、数量以十进制字符串出入。
- 错误沿用既有 `AppError` 映射；Zod strict 校验。
- 编号在事务内按天生成，避免并发重号。

**校验清单**

- `customerId` 必填且属同租户；`contactId` 若填须属同一客户。
- `fabricId` 须属同租户；`fabricSupplierId` 若填须属同一面料；`fabricSupplierQuoteId` 若填须属该货源。
- `currency = CNY` 时 `exchangeRate` 强制 1；`USD` 时必须 > 0。
- 明细行至少一行；`quantity > 0`；`deliveredQuantity ≥ 0` 且 `≤ quantity`。
- 税额非负；价格非负数。
- 成本自动带出规则：手工 `costPrice` 优先；否则取关联采购报价，报价为 CNY 直接采用，非 CNY 折算失败时报错并提示手填（与报价单完全一致）。

## 8. UI 设计（草案）

**侧边栏**：接通现有「订单」入口（当前为占位）。

**列表页**

- 统计卡：订单总数、进行中（已确认 + 备货中 + 已发货）、本月新增、逾期未交付。
- 筛选：关键词（单号 / 客户 / 面料）、状态、客户、面料、交期范围、交付状态。
- 表格列：单号、客户、下单日期、要求交期、明细数（面料数）、含税金额合计、毛利、交付状态、状态徽标。
- 逾期行：要求交期列红字 + 「逾期 N 天」徽标。
- 加载 / 失败 / 重试 / 空 / 竞态保护沿用现有页面写法。

**新建 / 编辑抽屉**

- 分区：客户信息 → 条款与币种（含税率、汇率）→ 收货信息 → 明细行 → 备注。
- 明细行：面料选择器（可重复选同一面料）、色号备注、数量、单位（快照、只读）、单价、可选采购货源与采购报价（带出成本）、行税率。
- 右侧实时汇总：不含税合计、含税合计、成本合计、毛利与毛利率；有人行缺成本时提示「部分行无成本参考」。

**详情抽屉**

- 顶部：单号、状态徽标、来源报价单号、操作按钮（编辑 / 确认 / 开始备货 / 发货 / 完成 / 取消）。
- 信息区：客户与联系人、下单日期与要求交期、贸易与付款条款、收货信息、备注。
- 汇总卡：含税金额、成本、毛利与毛利率、交付进度。
- 明细表：面料、色号、数量、单价、含税金额、成本、毛利、已交付 / 未交付。
- 交付登记：在 `producing` / `shipped` 状态下按行填写已交付数量，保存后刷新派生状态。

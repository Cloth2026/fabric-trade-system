### 1. 面料货源与采购报价维护

这是下一项优先产品任务，目标是把详情中的供应商与采购标签页从只读变为可维护闭环。

范围：

- 为已有面料添加供应商货源。
- 选择供应商及其生产单元。
- 新增采购报价。
- 查看和展开报价历史。
- 设置或调整首选货源。
- 记录供应商样品状态和质量差异。
- 验证生产单元属于当前租户和所选供应商。
- 通过事务写入关系、报价和操作日志。

仍按以下流程推进：

1. 静态 UI 原型。
2. 用户确认产品字段和交互。
3. API、数据校验和事务设计。
4. UI 真实接入。
5. 自动化测试与浏览器验收。

### 2. 面料编辑

- 先确认可编辑字段、工艺状态切换和供应商关系是否在同一编辑流程。
- 复用新增表单的字段分区、配置加载和控件，但不把详情改成 disabled 表单。
- 明确完整度重算、编号冲突和操作日志规则。

### 3. 寄样与客户反馈

- 建立寄样记录、寄样内容、客户、日期、状态和反馈。
- 与供应商样品状态区分，避免把客户寄样流程塞进 `FabricSupplier.sampleStatus`。

### 4. 客户管理

- 先做客户主档、联系人、类型、等级和状态，再接寄样与报价单。

### 5. 客户报价单

- 基于面料、客户和采购参考信息生成客户报价，不直接覆盖采购报价历史。

### 6. 订单

- 在客户、报价单和面料关系稳定后设计订单流程。

### 7. 库存

- 最后评审入库、批次、单位、库位、出入库和盘点流程，再启用 `FabricStockInBatch` 相关界面。

## 已知限制

- 面料库“可销售、待完善、本月新增”目前统计当前页，不是全库聚合；“面料总数”来自 API 总数。
- 本地开发库可能存在回归测试面料 `SDD-UI-REG-20260919-1645`。它不是 seed 或 Git 内容，应由使用者确认后单独清理。
- 面料详情中的编辑、添加货源和新增报价按钮目前仅显示后续开放提示。
- 当前使用临时单租户上下文，尚无真实登录和权限。
- 部分面料文件仍保留 `prototype` 命名，但页面已接入真实数据库 API。
- `FabricSupplier` 当前限制同一面料和供应商只有一条关系；未来若要把同供应商不同车间作为并列货源，需要先评审唯一约束。
- 完整度由保存时计算；如果未来通过独立 API 修改货源或工艺，必须同步重算完整度。
